# Инструкция по запуску

Пошагово, от чистой машины до работающего бота. Разделена на две части:
локальный запуск для проверки и развёртывание на сервере.

---

## Часть 1. Локальный запуск (Windows)

### Шаг 1. Проверьте, что установлено

```bash
docker --version          # нужен Docker 24+
docker compose version    # нужна версия v2
```

Если команд нет — поставьте [Docker Desktop](https://www.docker.com/products/docker-desktop/)
и перезагрузите компьютер.

Python и Node.js **не нужны** — всё собирается внутри контейнеров.

### Шаг 2. Запустите Docker Desktop

Откройте приложение и дождитесь, пока значок кита перестанет мигать. Пока он
мигает, все команды `docker` будут падать с ошибкой про `dockerDesktopLinuxEngine`.

### Шаг 3. Доступ к реестру образов

Симптом: при запуске падает с

```
Get "https://registry-1.docker.io/v2/": net/http: request canceled
(Client.Timeout exceeded while awaiting headers)
```

Причина — Docker не может скачать образы. Дальше по порядку, от частого к редкому.

#### 3.1. Проверьте VPN

**Это самая частая причина на машине с VPN.** Браузер и `curl` работают, а Docker
нет — потому что VPN-клиент (Happ, Hiddify, Nekoray, Clash и подобные) заворачивает
трафик только с хоста, а Docker работает внутри виртуальной машины WSL2, которая в
туннель не попадает.

Проверить, что дело в этом:

```bash
curl -s -o /dev/null -w "%{http_code}" https://registry-1.docker.io/v2/
```

Если с хоста возвращается `401`, а `docker pull` при этом висит и падает по таймауту —
причина именно в туннеле.

Что делать, любой из вариантов:

1. **Включить в VPN-клиенте режим TUN с захватом WSL.** В Happ и Hiddify это обычно
   «TUN mode» или «System-wide proxy». В настройках должно быть разрешено проксировать
   локальные подсети — WSL2 использует адреса `172.16.0.0/12`.

2. **Отдать Docker прокси явно.** Узнайте порт HTTP-прокси своего клиента (у Happ и
   Hiddify обычно `10809`, у Clash `7890`), затем:
   **Docker Desktop → Settings → Resources → Proxies** → включить **Manual proxy
   configuration** и вписать в оба поля:
   ```
   http://host.docker.internal:10809
   ```
   Нажать **Apply & Restart**.

3. **Выключить VPN на время скачивания образов.** Если Docker Hub у провайдера
   открывается напрямую — это самый простой путь. После того как образы скачаны,
   VPN можно включить обратно: собранные образы больше не требуют сети.

#### 3.2. Если VPN ни при чём — пропишите зеркала

**Docker Desktop → Settings → Docker Engine**, добавьте в JSON:

```json
"registry-mirrors": [
  "https://dockerhub.timeweb.cloud",
  "https://huecker.io",
  "https://mirror.gcr.io"
]
```

**Apply & Restart**.

Важно: править файл `C:\Users\<вы>\.docker\daemon.json` вручную бесполезно —
Docker Desktop перезаписывает его своими настройками. Меняйте только через GUI.

#### 3.3. Проверка

```bash
docker pull redis:7-alpine
```

Скачалось — значит, проблема решена, переходите к шагу 4.

### Шаг 4. Создайте файл настроек

```bash
cp .env.example .env
```

Откройте `.env` и заполните обязательное:

```bash
POSTGRES_PASSWORD=<придумайте пароль>
SECRET_KEY=<длинная случайная строка, 64 символа>
FIRST_ADMIN_EMAIL=admin@example.ru
FIRST_ADMIN_PASSWORD=<придумайте пароль>
```

Сгенерировать значения:

```bash
openssl rand -base64 24   # для POSTGRES_PASSWORD
openssl rand -hex 32      # для SECRET_KEY
```

### Шаг 5. Проверьте порты

Проект занимает порты 5432, 6379, 8080, 5173, 8100. Если что-то из них уже
занято (частый случай — установленный PostgreSQL на 5432), поменяйте в `.env`:

```bash
POSTGRES_HOST_PORT=5433
API_HOST_PORT=8081
```

Проверить занятость в Windows:

```bash
netstat -ano | findstr :5432
```

Внутри Docker контейнеры общаются по именам, так что смена этих портов ни на что
не влияет, кроме доступа с вашего компьютера.

### Шаг 6. Запустите

```bash
docker compose up -d --build
```

Первый запуск идёт 10–20 минут: скачиваются базовые образы и собираются свои.

> Если сборка падает с `image "...": already exists` — это особенность BuildKit в
> Docker Desktop. Запустите так:
> ```bash
> BUILDX_NO_DEFAULT_ATTESTATIONS=1 docker compose up -d --build
> ```

### Шаг 7. Дождитесь готовности

```bash
docker compose ps
```

Все сервисы должны быть в статусе `running`, а `api` и `embeddings` — ещё и
`healthy`. Контейнер `embeddings` первым запуском качает около 2.5 ГБ моделей,
это занимает несколько минут:

```bash
docker compose logs -f embeddings
```

Ждите строку `Модели загружены, сервис готов`.

### Шаг 8. Откройте админ-панель

http://localhost:5173

Вход — тем, что указали в `FIRST_ADMIN_EMAIL` и `FIRST_ADMIN_PASSWORD`.
Сразу смените пароль: **Система → Сменить свой пароль**.

### Шаг 9. Проверьте состояние

Раздел **Система** показывает все компоненты. Ожидаемая картина при локальном
запуске без GPU:

| Компонент | Состояние |
|---|---|
| База данных | работает |
| Redis | работает |
| Эмбеддинги | работает |
| Языковая модель | **недоступна** — это нормально, vLLM требует GPU |

## Часть 2. Подключение языковой модели

Без неё бот найдёт материалы, но не сформирует ответ. Три варианта.

### Вариант А. GigaChat — быстрее всего

1. Зарегистрируйтесь на [developers.sber.ru/studio](https://developers.sber.ru/studio)
2. Создайте проект **GigaChat API**, нажмите «Получить ключ»
3. Скопируйте поле **«Авторизационные данные»** — это одна длинная строка

В `.env`:

```bash
LLM_PROVIDER=gigachat
GIGACHAT_AUTH_KEY=<строка из кабинета>
GIGACHAT_SCOPE=GIGACHAT_API_PERS
```

```bash
docker compose up -d api worker vkbot
```

### Вариант Б. Ollama — локально, без GPU

Работает на процессоре, отвечает медленно (единицы токенов в секунду), зато
полностью автономно.

```bash
docker compose --profile ollama up -d
docker compose exec ollama ollama pull qwen3:8b
```

В `.env`:

```bash
LLM_PROVIDER=ollama
LLM_MODEL=qwen3:8b
LLM_BASE_URL=http://ollama:11434/v1
```

```bash
docker compose up -d api worker vkbot
```

### Вариант В. vLLM — боевой режим, нужен GPU

```bash
docker compose --profile gpu up -d --build
```

Первый запуск качает веса модели (около 10 ГБ) — до получаса. Следите:

```bash
docker compose logs -f llm
```

## Часть 3. Наполнение базы знаний

Порядок важен: без материалов бот будет отвечать «нет в базе» на всё.

1. **Материалы** → «Загрузить материал». Укажите название, авторов, год и раздел —
   эти данные попадут в ссылку на источник под ответом. Индексация идёт в фоне,
   прогресс виден в списке. Дождитесь статуса «Готов».

2. **Термины** → «Импорт CSV». Возьмите за образец `samples/glossary_example.csv`.
   Без словаря запрос «наружная сонная артерия» может не найти фрагмент,
   подписанный «arteria carotis externa».

3. **Изображения** — иллюстрации атласов с перечнем структур на русском и латыни.
   Заполните поле о правах на использование.

4. **Проверка** — задайте вопрос и посмотрите, какие фрагменты нашлись и с какими
   оценками. Это главный инструмент настройки.

## Часть 4. Подключение VK

1. Сообщество → **Управление → Сообщения** → включить
2. **Управление → Работа с API → Ключи доступа** → создать ключ с правами
   «Сообщения сообщества»
3. **Работа с API → Long Poll API** → включить, версия 5.199, отметить событие
   «Входящее сообщение»

В `.env`:

```bash
VK_ENABLED=true
VK_GROUP_TOKEN=vk1.a....
VK_GROUP_ID=123456789
```

```bash
docker compose up -d vkbot
docker compose logs -f vkbot
```

Ждите строку `vk_longpoll_connected`, затем напишите сообществу.

## Часть 5. Развёртывание на сервере

### Шаг 1. Проверьте сервер

```bash
bash deploy/check-server.sh
```

Скрипт проверит Docker, видеокарту, NVIDIA Container Toolkit, память, диск и
заполненность `.env`. Ничего не меняет — только сообщает, что доделать.

### Шаг 2. Настройте прод-режим

В `.env`:

```bash
ENVIRONMENT=production
PUBLIC_DOMAIN=anatomy-bot.ваш-домен.ру
ACME_EMAIL=admin@ваш-домен.ру
CORS_ORIGINS=https://anatomy-bot.ваш-домен.ру
```

Домен должен указывать на IP сервера, порты 80 и 443 — открыты. Caddy выпустит
сертификат автоматически.

### Шаг 3. Запустите

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml --profile gpu up -d --build
```

Отличия от локального режима: бэкенд под gunicorn с четырьмя воркерами, фронтенд
собран в статику и раздаётся nginx, порты базы и Redis наружу не публикуются,
перед всем стоит Caddy с HTTPS.

### Шаг 4. Проверьте

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml ps
curl -I https://anatomy-bot.ваш-домен.ру
```

## Повседневные команды

```bash
docker compose ps                    # что запущено
docker compose logs -f api           # логи бэкенда
docker compose logs -f worker        # логи индексации
docker compose restart api           # перезапустить сервис
docker compose down                  # остановить всё
docker compose down -v               # остановить и стереть данные (!)

make backup                          # дамп базы в backups/
make restore f=backups/файл.sql.gz   # восстановление
```

Резервная копия должна включать не только базу, но и том `storage` — в нём лежат
исходные файлы учебников и изображений.

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| `dockerDesktopLinuxEngine: The system cannot find the file` | Docker Desktop не запущен |
| `request canceled while awaiting headers` при скачивании | Docker не видит реестр. Чаще всего виноват VPN — см. шаг 3.1 |
| `Ports are not available ... 5432` | Порт занят. Смените `POSTGRES_HOST_PORT` в `.env` |
| `image "...": already exists` | Соберите с `BUILDX_NO_DEFAULT_ATTESTATIONS=1` |
| Бот отвечает «нет в базе» на всё | Материалы не загружены или не проиндексированы — проверьте раздел «Материалы» |
| Индексация висит в статусе «В очереди» | Не запущен `worker`: `docker compose up -d worker` |
| Поиск ничего не находит сразу после запуска | `embeddings` ещё качает модели — `docker compose logs -f embeddings` |
| Ошибка генерации при любом вопросе | Не подключена языковая модель — часть 2 |
| VK-бот молчит | Проверьте `VK_ENABLED=true`, права ключа и включённый Long Poll |

Состояние всех компонентов всегда видно в админ-панели, раздел **Система**.
