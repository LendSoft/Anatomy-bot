# Образовательный бот по анатомии человека

RAG-система для студентов медицинского университета: отвечает на вопросы по анатомии
строго по загруженным учебным материалам кафедры, всегда указывает источник и честно
отказывается отвечать, когда данных в базе нет.

Общение со студентами идёт через сообщество ВКонтакте, управление — через веб-панель.

## Из чего состоит

| Компонент | Технология | Назначение |
|---|---|---|
| Админ-панель | React 18 + Vite + Ant Design | Статистика, логи, промпты, параметры, тесты, загрузка материалов |
| Бэкенд | FastAPI + SQLAlchemy 2 (async) + Alembic | API и RAG-пайплайн |
| База данных | PostgreSQL 16 + pgvector | Материалы, векторы, логи, настройки |
| Очередь | Redis + ARQ | Индексация учебников, прогоны тестов |
| Эмбеддинги | BAAI/bge-m3 + bge-reranker-v2-m3 (CPU) | Векторизация и переранжирование |
| Языковая модель | vLLM + Qwen3-14B-AWQ (GPU), резерв — GigaChat | Формирование ответа |
| VK-бот | Long Poll | Общение со студентами |
| Прокси | Caddy | HTTPS с автоматическим сертификатом |

### Как формируется ответ

```
вопрос → расширение по словарю ru↔lat
       → гибридный поиск (pgvector + полнотекстовый Postgres)
       → переранжирование кросс-энкодером
       → проверка порога релевантности ──→ ниже порога: «нет в базе»
       → генерация с обязательными ссылками [1], [2]
       → подбор иллюстрации из атласа
```

Порог релевантности — основная защита от выдуманных ответов. Если лучший найденный
фрагмент набрал меньше порога, бот отвечает отказом, а не догадкой. Порог настраивается
из панели.

## Где взять токены и ключи

**Все секреты проекта лежат в одном файле — `.env` в корне.** Больше нигде: ни в коде,
ни в образах, ни в базе. Файл в `.gitignore`, в репозиторий не попадает. Шаблон со
всеми полями и комментариями — `.env.example`.

| Что | Переменная | Где взять | Обязателен |
|---|---|---|---|
| Пароль базы данных | `POSTGRES_PASSWORD` | Придумать: `openssl rand -base64 24` | да |
| Ключ подписи сессий | `SECRET_KEY` | Сгенерировать: `openssl rand -hex 32` | да |
| Пароль первого входа | `FIRST_ADMIN_PASSWORD` | Придумать, сменить после первого входа | да |
| Ключ GigaChat | `GIGACHAT_AUTH_KEY` | developers.sber.ru/studio → проект GigaChat API → «Авторизационные данные» | для резервного провайдера |
| Ключ сообщества VK | `VK_GROUP_TOKEN` | Сообщество → Управление → Работа с API → Ключи доступа | для работы бота |
| Токен Hugging Face | `HUGGING_FACE_HUB_TOKEN` | huggingface.co → Settings → Access Tokens | только для закрытых моделей |

Первые три нужны всегда — без них система не поднимется. Остальные зависят от того,
что вы включаете.

### GigaChat

1. Зайдите на [developers.sber.ru/studio](https://developers.sber.ru/studio), создайте
   проект **GigaChat API**.
2. В разделе «Настройки API» нажмите **Получить ключ**. Появится поле
   **«Авторизационные данные»** — это одна длинная строка в base64.
3. Скопируйте её целиком в `GIGACHAT_AUTH_KEY`. Именно эту строку, а не Client ID и не
   Client Secret по отдельности — клиент сам обменивает её на access token и обновляет
   его каждые 30 минут.

Если в кабинете выданы только Client ID и Client Secret по отдельности, заполните
`GIGACHAT_CLIENT_ID` и `GIGACHAT_CLIENT_SECRET` — ключ соберётся автоматически.

Выберите нужный scope: `GIGACHAT_API_PERS` для физлиц, `GIGACHAT_API_B2B` для ИП и
юрлиц по предоплате, `GIGACHAT_API_CORP` для корпоративного доступа. Неверный scope
даёт ошибку авторизации, а не отказ в ответе.

**Про сертификат.** Сервер GigaChat подписан НУЦ Минцифры, которого нет в стандартном
Linux-образе. По умолчанию стоит `GIGACHAT_VERIFY_SSL=false` — так проще стартовать, но
для прода лучше включить проверку:

```bash
bash deploy/install-russian-ca.sh
# затем в .env:
GIGACHAT_VERIFY_SSL=/certs/russian_trusted.pem
docker compose up -d api worker vkbot
```

### Ключ доступа VK

1. Сообщество → **Управление → Сообщения** → включить.
2. **Управление → Работа с API → Ключи доступа** → создать ключ с правами
   **«Сообщения сообщества»**. Начинается с `vk1.a...`.
3. **Работа с API → Long Poll API** → включить, версия 5.199, в типах событий отметить
   **«Входящее сообщение»**.
4. `VK_GROUP_ID` — числовой ID сообщества без минуса, виден в адресе страницы или в
   разделе «Адрес страницы».

## Быстрый старт

Нужен Docker с Docker Compose v2. Для локальной модели — NVIDIA GPU и NVIDIA Container Toolkit.

```bash
cp .env.example .env
```

Минимум, который нужно заполнить в `.env`:

```bash
POSTGRES_PASSWORD=...              # openssl rand -base64 24
SECRET_KEY=...                     # openssl rand -hex 32
FIRST_ADMIN_EMAIL=admin@example.ru
FIRST_ADMIN_PASSWORD=...
```

Дальше выберите один из трёх вариантов — они отличаются тем, откуда берётся
языковая модель. Всё остальное (база, поиск, админка, VK-бот) поднимается одинаково.

**Вариант А — есть GPU (боевой режим).** Модель работает локально на vLLM:

```bash
docker compose --profile gpu up -d --build
```

**Вариант Б — GPU нет, но есть ключ GigaChat.** Самый быстрый способ увидеть
работающего бота. В `.env`:

```bash
LLM_PROVIDER=gigachat
GIGACHAT_AUTH_KEY=...
```

```bash
docker compose up -d --build
```

**Вариант В — GPU нет и облако не нужно.** Модель на процессоре через Ollama,
отвечает медленно (единицы токенов в секунду), но полностью автономно:

```bash
docker compose --profile ollama up -d --build
docker compose exec ollama ollama pull qwen3:8b
```

В `.env`: `LLM_PROVIDER=ollama`, `LLM_MODEL=qwen3:8b`, `LLM_BASE_URL=http://ollama:11434/v1`

> Простой `docker compose up -d` без профиля и без GigaChat поднимет всё, кроме модели:
> админка откроется, документы загрузятся и проиндексируются, но на вопрос бот ответит
> ошибкой генерации. Проверить, что с моделью, можно в разделе **Система**.

После запуска:

* админ-панель — http://localhost:5173
* API и документация — http://localhost:8080/docs

Полезные команды:

```bash
docker compose ps                  # что запущено
docker compose logs -f api         # логи бэкенда
docker compose logs -f embeddings  # прогресс скачивания моделей
docker compose down                # остановить
```

Первый вход — под учёткой из `FIRST_ADMIN_EMAIL` / `FIRST_ADMIN_PASSWORD`. Пароль
поменяйте сразу, в разделе «Система».

При первом запуске контейнер `embeddings` скачивает модели (~2.5 ГБ) — это занимает
несколько минут, пока он не готов, индексация и поиск не работают. Состояние видно в
разделе «Система».

## Прод

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml --profile gpu up -d --build
```

Отличия от разработки: порты БД, Redis и LLM наружу не публикуются, бэкенд под gunicorn
с четырьмя воркерами, фронтенд собран в статику и раздаётся nginx, перед всем стоит Caddy
с автоматическим Let's Encrypt.

Перед запуском в `.env`:

```bash
ENVIRONMENT=production
PUBLIC_DOMAIN=anatomy-bot.example.ru   # домен должен указывать на сервер
ACME_EMAIL=admin@example.ru
CORS_ORIGINS=https://anatomy-bot.example.ru
```

## Подключение VK

Ключ и ID сообщества берутся так, как описано выше в разделе про токены. Дальше в `.env`:

```bash
VK_ENABLED=true
VK_GROUP_TOKEN=vk1.a....
VK_GROUP_ID=123456789
```

```bash
docker compose up -d vkbot
```

Пока `VK_ENABLED=false`, контейнер `vkbot` просто простаивает — это нормально.

## Окружение Python для разработки

**Для запуска проекта оно не нужно.** Зависимости ставит Docker: `requirements.txt`
копируется в образ и устанавливается при сборке, внутри контейнера venv нет.

Локальное окружение полезно только на вашей машине — чтобы редактор видел импорты и
чтобы гонять тесты с линтером без пересборки образов. Не нужно — просто удалите
`backend/.venv`, в образ она всё равно не попадает.

Если понадобится, создаётся двумя командами:

```bash
cd backend
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt -r requirements-dev.txt
```

На Linux и macOS путь к интерпретатору — `.venv/bin/python`.

```bash
.venv/Scripts/python.exe -m pytest              # тесты
.venv/Scripts/python.exe -m ruff check app      # линтер
```

В VS Code выберите этот интерпретатор: `Ctrl+Shift+P` → **Python: Select Interpreter**.

Зависимости разделены на два файла: `requirements.txt` попадает в образ Docker,
`requirements-dev.txt` — только в локальное окружение.

## Выбор модели

Значение по умолчанию — `Qwen/Qwen3-14B-AWQ`: помещается в 12–16 ГБ VRAM и хорошо
держит русский язык. Меняется переменной `VLLM_MODEL`.

| VRAM | Рекомендуемая модель |
|---|---|
| 12 ГБ | `Qwen/Qwen3-8B-AWQ` |
| 16 ГБ | `Qwen/Qwen3-14B-AWQ` |
| 24 ГБ | `t-tech/T-pro-it-2.0` (AWQ) |
| 48 ГБ+ | `google/gemma-3-27b-it` |

Эмбеддинги и реранкер намеренно вынесены в отдельный контейнер на CPU — на карте
12–16 ГБ место нужно самой языковой модели.

### Резервный провайдер

По умолчанию это **GigaChat**. Включается в `.env`:

```bash
LLM_FALLBACK_ENABLED=true
LLM_FALLBACK_PROVIDER=gigachat
LLM_FALLBACK_MODEL=GigaChat-2      # GigaChat-2-Pro | GigaChat-2-Max
GIGACHAT_AUTH_KEY=...
```

Резерв срабатывает, когда локальная модель не ответила: контейнер `llm` не поднялся,
GPU занят, кончилась память. В логах диалога такой ответ помечен провайдером
`gigachat` — видно, какие ответы получены не на локальной модели.

GigaChat можно сделать и основным, без правки `.env`: **Параметры → Модель → Провайдер**.
Удобно, пока сервер с GPU ещё не готов.

Две особенности GigaChat, учтённые в клиенте: температура не может быть нулевой
(подменяется на минимально допустимую), а ответ с `finish_reason: blacklist` означает,
что тема попала под ограничения модели — такой случай логируется отдельно.

### Ollama как альтернатива vLLM

vLLM быстрее и лучше держит нагрузку, но требует GPU и подходящей квантованной модели.
Ollama проще: одна команда на скачивание модели, работает и без видеокарты (медленно —
единицы токенов в секунду).

```bash
docker compose --profile ollama up -d
docker compose exec ollama ollama pull qwen3:8b
```

Затем в `.env`:

```bash
LLM_PROVIDER=ollama
LLM_MODEL=qwen3:8b
LLM_BASE_URL=http://ollama:11434/v1
```

Либо переключите провайдера прямо из админки — адрес подставится сам.

### Доступные провайдеры

| Провайдер | Где работает | Когда выбирать |
|---|---|---|
| `vllm` | контейнер `llm`, нужен GPU | основной режим на боевом сервере |
| `ollama` | контейнер `ollama`, GPU необязателен | разработка, проба модели, сервер без карты |
| `gigachat` | облако Сбера | резерв и период, пока GPU не готов |

Никаких обращений к зарубежным сервисам в проекте нет: vLLM и Ollama работают внутри
вашего контура, GigaChat — российский сервис. Формат запросов у vLLM и Ollama называется
«OpenAI-совместимый», но это только название протокола.

## Наполнение базы знаний

1. **Материалы** — загрузите PDF или DOCX, укажите название, авторов, год и раздел курса.
   Эти данные попадают в ссылку на источник под ответом бота, поэтому заполняйте их
   аккуратно. Индексация идёт в фоне, прогресс виден в списке.
2. **Термины** — загрузите словарь ru ↔ lat (CSV: `term_ru,term_lat,synonyms,section,definition`).
   Без него запрос «наружная сонная артерия» может не найти фрагмент, подписанный
   «arteria carotis externa».
3. **Изображения** — загрузите иллюстрации атласов, перечислите изображённые структуры
   на русском и латыни. Обязательно заполните поле о правах на использование.

Отсканированные PDF без текстового слоя распознаются автоматически (tesseract, rus+eng),
если в параметрах включён OCR. Это заметно медленнее — качество распознавания стоит
проверить в разделе «Материалы → Фрагменты».

## Проверка качества

Раздел **Тестирование** реализует требования раздела 9 ТЗ:

1. Создайте набор вопросов, например «Черепные нервы».
2. Внесите вопросы с эталонными ответами преподавателя — вручную или импортом CSV
   (`question,reference_answer,expected_source,should_refuse`).
3. Добавьте несколько вопросов вне программы с отметкой «должен отказаться» — это
   проверка того, что бот не выдумывает.
4. Запустите прогон. Ответы оценит модель-судья, преподаватель может перекрыть оценку
   вручную.

Прогон сохраняет слепок настроек и версию промпта, поэтому результаты двух прогонов
сравнимы между собой.

## Настройка качества ответов

| Симптом | Что делать |
|---|---|
| Слишком часто отвечает «нет в базе» | Проверьте «Логи» — если фрагменты находятся, но с низкими оценками, снизьте порог релевантности. Если не находятся вовсе, не хватает материалов |
| Ответы поверхностные | Увеличьте «фрагментов в контекст» и максимум токенов, поставьте стиль «подробный» |
| Попадаются выдуманные детали | Поднимите порог релевантности, снизьте температуру до 0.1, добавьте пример отказа в «Идеальные ответы» |
| Не находит по латинскому названию | Пополните словарь терминов, снизьте вес векторного поиска в сторону полнотекстового |
| Ответы приходят медленно | Уменьшите «кандидатов из базы», проверьте загрузку GPU |
| В логах провайдер `gigachat` вместо `vllm` | Локальная модель не отвечает — смотрите «Система» и логи контейнера `llm` |

## Диагностика

| Проблема | Причина и решение |
|---|---|
| `Не задан ключ авторизации GigaChat` | Пустой `GIGACHAT_AUTH_KEY`. Проверьте, что скопирована строка из поля «Авторизационные данные», а не Client ID |
| `GigaChat не выдал токен (401)` | Неверный ключ или scope. Для физлиц нужен `GIGACHAT_API_PERS` |
| `certificate verify failed` при обращении к GigaChat | Не установлен сертификат НУЦ Минцифры. Запустите `bash deploy/install-russian-ca.sh` либо временно поставьте `GIGACHAT_VERIFY_SSL=false` |
| `тема попала под ограничения модели` | GigaChat отклонил запрос своим фильтром. Ответ будет получен от резервного провайдера, если он настроен |
| При пересборке: `image "...": already exists` | Особенность BuildKit в Docker Desktop — конфликт attestation-манифестов. Соберите с `BUILDX_NO_DEFAULT_ATTESTATIONS=1 docker compose up -d --build` или используйте `make up`, там это уже прописано |
| Индексация висит в статусе «В очереди» | Не запущен контейнер `worker`: `docker compose up -d worker` |
| Поиск не находит ничего после загрузки | Контейнер `embeddings` ещё качает модели. Состояние — в разделе «Система» |
| VK-бот не отвечает | Проверьте `VK_ENABLED=true`, права ключа на сообщения и включённый Long Poll с событием «Входящее сообщение» |

## Резервное копирование

```bash
make backup                                    # дамп в backups/

```

Отдельно нужно копировать том `storage` — в нём лежат исходные файлы учебников и
изображений.

## Ограничения текущей версии

* Обучающий режим с тестированием студентов (раздел 7 ТЗ) не реализован — по ТЗ он
  необязателен для первой версии. Модель данных под него готова.
* Изображения ищутся по текстовому описанию, не по содержимому картинки.
  Мультимодальная модель подключается заменой провайдера LLM.
* DOCX не разбит на страницы, поэтому в ссылке на источник для них указывается раздел,
  а не номер страницы.
